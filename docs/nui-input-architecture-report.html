NUI Input/Val 变量架构诊断报告

Neon3 v0.2.7 · 文字排版修复后架构审查 · 2026-09-12

核心结论

确认的问题
UiInputValue 只有标量枚举，无 Struct/Object/Array。复杂数据必须拆成独立变量，24格背包需声明24个 slot。
刷新影响
GPU 端 pack_inputs 全量重打包所有 slot，无增量上传。N 个变量中任一个变化，整个 input buffer 重新上传。
类型缺口
Vec2/Vec4/Color/Enum/AssetHandle 在 GPU pack_inputs 中未实现（_ => {}），shader 读不到。
SDK 已有能力
ObservableStore 支持 CollectionStore/SelectionStore/事务/增量 diff，但 runtime 端无对应 input 类型承接。

二、问题诊断（实际证据）

P0 · 无结构体 Input 类型

证据：UiInputValue 枚举只有 11 种标量，无 Struct/Object/Map/Array。

实际痛点：案例中 24 格背包必须写成：

apple_in_slot_01, apple_in_slot_02, ... apple_in_slot_24 orange_in_slot_01, orange_in_slot_02, ... orange_in_slot_24 → N种物品 × 24格 = 24N 个独立变量

后果：变量爆炸、命名冗余、无法整体替换、事务边界模糊。

P0 · GPU 全量重打包无增量

证据：pack_inputs() 遍历 inputs.values 全部 slot，每 slot 固定 16 字节。

刷新路径：

SDK 增量 changes → Runtime 全量 resolved → pack_inputs 遍历全部 N 个 slot → write_buffer 整体上传 GPU

后果：100 个 slot 中改 1 个，仍打包上传 100×16=1600 字节。slot 越多浪费越大。

P1 · GPU 类型支持不完整

证据：pack_inputs match 中：

UiInputValue::Vec2 { .. } | Vec4 | Color | Enum | AssetHandle | CanvasData => {}

后果：声明了这些类型的 slot，shader 中读到的是零值。NUI Flow 解析器甚至不支持声明 vec2/vec4/color。

P1 · Collection 与 Input 脱节

证据：SDK 有 CollectionStore（支持 add/remove/move/replace），但 runtime 的 UiInputValue 无列表类型。

当前出路：Collection 只能通过 UiGridInputSlot → DataGrid 渲染。

后果：集合数据无法绑定到普通节点属性（如可见性、位置、文本），只能在表格中显示。

P2 · NUI Flow 无表达式

证据：nui_flow.rs 头部声明 "It has no evaluator, expressions, callbacks"。

后果：派生状态（如 row_5_visible = capacity != "small"）必须在 SDK 端计算后写成独立 slot。进一步加剧变量爆炸。

P2 · StateMachine 只管样式

证据：NuiFlowState 只有 styles（bounds/background/border/opacity），无数据值。

后果：状态切换只能动画样式，不能切换数据/可见性逻辑。复杂交互必须靠 input slot + branch predicate 模拟。

三、缺失功能清单

功能 当前状态 优先级 影响范围
Struct/Object input 类型 缺失 P0 schema/runtime/GPU/SDK 全链路
Array/List input 类型 缺失（仅 DataGrid） P0 集合数据绑定到节点属性
GPU 增量上传（partial update） 全量重打包 P0 大规模 slot 时的性能
GPU 完整类型支持（Vec2/4/Color/Enum） pack_inputs 中 => {} P1 shader 中使用向量/颜色输入
结构体字段级绑定 缺失 P1 节点属性绑定到 struct.field
NUI Flow 受限表达式 无表达式 P2 减少 SDK 端派生变量
派生状态/计算属性（runtime 端） 缺失 P2 computed input，减少 SDK 同步
NUI Flow 声明 vec2/vec4/color 解析器不支持 P2 Flow 文档中声明向量输入

四、推进路线（分阶段）

1
第1阶段
1-2天
补齐 GPU 类型支持 + 增量上传
  • pack_inputs 实现 Vec2/Vec4/Color/Enum 的 GPU 打包（每 slot 16 字节足够容纳 vec4）
  • NUI Flow 解析器增加 vec2/vec4/color 类型声明
  • 基于 changed_slots 做 partial buffer update（只 write 变化的 16 字节槽位）
  • 验收：shader 中能读到 vec4/color 输入；100 slot 改 1 个只上传 16 字节
2
第2阶段
3-5天
Struct input 类型（核心）
  • UiInputValue::Struct { fields: BTreeMap<String, UiInputValue> } — 支持嵌套
  • UiInputKind::Struct { fields: BTreeMap<String, UiInputKind> } — schema 声明
  • GPU 布局：struct 展开为连续的 16 字节槽位，字段偏移由 schema 计算
  • NUI Flow 语法：input player struct { name text, hp f32, pos vec2 }
  • SDK 端：store.value("player.hp").set(0.8) 字段级访问，自动生成 struct 更新
  • 字段级绑定：bind text_value $player.name
  • 验收：背包案例从 24N 个变量缩减为 1 个 struct array
3
第3阶段
3-5天
Array input 类型 + Collection 直通
  • UiInputValue::Array { elements: Vec<UiInputValue>, element_kind }
  • 固定长度数组走 GPU uniform buffer；动态长度走 storage buffer + length uniform
  • SDK CollectionStore → Array input 自动序列化，不再仅限 DataGrid
  • 数组元素绑定：bind visible $slots[i].occupied（需索引表达式）
  • 验收：背包用 input slots array[24] of struct { item text, count u32 } 声明
4
第4阶段
后续
受限表达式 + 派生状态
  • NUI Flow 增加受限表达式：比较（==/!=/>/<）、逻辑（and/or/not）、算术（+/-/*）
  • 派生 input：input row5_visible bool = $capacity != "small"，runtime 端计算
  • 表达式在 UI Runtime 求值，不进入 GPU，不承载领域规则（符合 AGENTS.md 边界）
  • 验收：案例中 row_5_visible/row_6_visible 等派生变量无需 SDK 端同步

五、立即可做的低成本改进（不改动架构）

① 补齐 pack_inputs 类型
约 30 行代码，Vec2/Vec4/Color/Enum 写入 16 字节槽位
② NUI Flow 增加 vec2/vec4/color 声明
解析器加 3 个分支，约 20 行代码
③ 基于 changed_slots 的 partial upload
UiResolvedInputs 已有 changed_slots 字段，GPU 端按偏移 write_buffer
④ SDK 端 struct 模拟（过渡方案）
store.value("player.hp") 自动映射为 "player__hp" 扁平 key，runtime 端暂不感知
