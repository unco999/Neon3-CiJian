## 四、已实现的关键性能优化

### 渲染路径优化

1. **pointer down 不再重绘整张 ID 图** (Phase 4)
   - 旧行为：每次 pointer down 创建 command encoder，clear R32Uint，draw_hit_id，copy one pixel，map readback（约 0.5ms GPU 时间）
   - 新行为：从渲染循环已完成的持久纹理中读一个像素（约 0.01ms GPU 时间，无 draw）

2. **ID 帧与绑定映射 frame pairing** (Phase 5)
   - 旧行为：pointer 使用 `ui.hit_binding()`（可能来自不同帧）
   - 新行为：pointer 使用 `id_frame_bindings`（与 ID 纹理同一帧的快照）

3. **GPU buffer 预分配 512** (Phase 8)
   - 旧行为：所有 buffer 从 capacity=1 开始，每帧检查扩容，`next_power_of_two()` 后 `create_buffer`
   - 新行为：capacity=512 起步，仅在超过预算时扩容

### 文本渲染优化

4. **静态文本缓存** (Phase 8)
   - 旧行为：每帧调用 `layout_text()` 重新计算所有文本节点的位置/换行
   - 新行为：缓存 key 匹配时直接返回 `Vec<UiTextInstance>`，跳过 `layout_text()` 调用（包括 `ensure_glyph()` 循环）

### 可观察性

5. **结构化 JSONL 窗口** (Phase 1)
   - 旧行为：`eprintln!` 文本日志，不可被机器消费
   - 新行为：`println!` JSONL，每 60 帧输出，可被 probe 和监控系统消费

6. **debug.unified_id.inspect** (Phase 5)
   - 新增 RPC 方法，暴露 numeric_id ↔ node_path/intent 映射

### 可执行验收

7. **world_ui_perf_probe** (Phase 10)
   - 新增 13 步 JSONL 探针，覆盖 service health、surface open、fragment submit、ID frame wait、pointer hit、rapid click、ID map verify

## 七、关键数据流图

### 当前（施工后）的 pointer down 数据流

```
Bevy Host
  |  ECS Update: compute camera + anchor
  |  (Phase 2 待优化: latest-value coalescing)
  v
┌─────────────────────────────────────────────────┐
│ neon-wgpu-runtime (headless external server)     │
│                                                   │
│  Render Loop (every ~16ms)                        │
│  ├─ external_surface_snapshots()                  │
│  ├─ render()                                      │
│  │  ├─ clear color texture                        │
│  │  ├─ draw color pass                            │
│  │  ├─ draw depth pass (WorldUi)                  │
│  │  ├─ draw ID pass → external ring buffer        │
│  │  ├─ draw ID pass → pointer_hit_target (持久)   │ ← Phase 3
│  │  ├─ id_frame_sequence = frame_sequence          │
│  │  └─ id_frame_bindings = snapshot()              │ ← Phase 5
│  └─ push_frame_timing()                            │
│                                                     │
│  Pointer Event Handler                             │
│  ├─ read_completed_id_frame()                      │ ← Phase 4
│  │  ├─ enqueue_hit_readback(pointer_hit_target)    │
│  │  └─ poll → read numeric ID                      │
│  ├─ resolve binding via id_frame_bindings           │ ← Phase 5
│  └─ dispatch semantic event → Bevy Host            │
└─────────────────────────────────────────────────┘
```

### 期望的 Phase 2 完成后数据流

```
Bevy Host
  |  ECS Update:
  |  ├─ compute camera + anchor
  |  ├─ compare with WorldFrameSignature
  |  ├─ if changed: dirty=true, pending=latest
  |  └─ if !in_flight && dirty: send via world_latest_lane
  |
  |  Interaction (pointer events):
  |  └─ send via interaction_lane (independent RpcClient)
  |
  |  Response handling:
  |  ├─ in_flight=false
  |  └─ if pending exists: next Update sends latest
  v
WGPU Runtime (两条独立 RPC lane)
  ├─ world_latest_lane: camera + anchor (丢弃旧 backlog)
  └─ interaction_lane: pointer events (不等待 world lane)
```
