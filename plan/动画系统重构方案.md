
# Neon3 UI 动画系统重构方案

> 日期：2026-09-13
> 状态：v2 设计完成，待进入 runtime 施工
> 范围：`neon-ui-schema` / `neon-ui-runtime` / `neon-wgpu-runtime`

> [!abstract] 目标
> 建立一套边界清晰、可重定向、可测试的 NUI 动画系统。状态机负责回答“当前是什么状态、事件后应该到什么状态”，动画系统负责回答“视觉如何从当前值到目标值”，WGPU 只负责按统一时钟采样并渲染。节点生命周期、属性过渡、状态表现和 GPU shader 参数不能再由同一个字段或同一段 if-else 承担。

> [!important] 架构原则
> 本文只讨论状态机和动画系统，不定义 IDE、案例视觉、窗口主题或业务领域模型。外部 Node host 可以使用 XState 等架构库，但 runtime 内部不复制一份 Node 状态，也不让 WGPU runtime 解释业务 intent。所有跨层交互必须经过明确的 visual target、animation command 和 revision。

---

## 一、当前机制的问题

### 1. `enter_transition` 语义混乱

- 字段名叫 `enter_transition`，但实际行为是任何 target visual 变化都可能触发新动画。
- `sample()` 只根据 `current != target` 创建 `ActiveTransition`，无法区分节点诞生、状态切换、拖拽和普通属性更新。
- 一个字段同时承担 enter、state transition 和 generic visual transition 三种职责。
- 动画来源不明确时，调用方无法判断是应该重启动画、继续当前动画还是立即跳到目标值。

### 2. 生命周期不完整

| 阶段 | 当前状态 | 问题 |
|---|---|---|
| 节点诞生 Enter | 有 `enter_transition` | NUI 无法直接声明，且 identity 处理不统一 |
| 状态转换 | 有 machine/motion | 状态机结果没有稳定进入 WGPU 动画执行层 |
| 属性更新 | `sample()` 隐式处理 | 普通更新和状态动画没有来源标记 |
| Hover/Pressed | 有本地 `UiVisualState` | 与 state machine 的 target 可能互相覆盖 |
| 节点销毁 Exit | 无 | 节点从 fragment 移除后直接消失 |
| 节点重新出现 | 未定义 | 旧 exit 动画可能删除新 identity |

### 3. 动画属性不足

当前 `UiTransitionState` 主要支持：

- `bounds`（位置和大小）。
- `background_color`、`border_color`、`border_width`、`corner_radius`。
- `opacity`。
- `numeric_value`。

缺失或边界不清晰的能力：

- `transform`：scale、rotation、translate、anchor。
- `text_color`。
- 多段 keyframe、delay、stagger、chain。
- 节点 exit 和完成后的真正移除。
- transform 后与视觉一致的 hit-test。
- shader 参数的独立动画轨道。

### 4. 状态机与渲染层脱节

- NUI 已经存在 `machine`、`state`、`motion`、`on`、`sync` 等语法。
- `neon-ui-runtime` 已有 `NuiFlowStateMachineRuntime`，可以 dispatch intent 并得到状态转换结果。
- `neon-wgpu-runtime` 没有正式消费状态转换结果的统一接口。
- showcase 和 animation probe 只能在 Rust 代码里手写 if-else 修改样式。
- 状态机的语义结果、fragment target 和 renderer current value 没有同一个 revision 链。

### 5. NUI 无法完整声明动画

- `enter_transition` 只能通过 JSON IR 设置。
- NUI parser 没有通用的 `enter`、`exit`、`transition` 节点属性。
- `motion` 只能被状态机 transition 引用，不能直接复用于节点生命周期。
- `from` 只覆盖少量属性，无法表达 transform 和颜色变化。
- 没有可静态检查的 motion 引用、参数范围和节点 identity 规则。

### 6. 快速切换可能崩溃

- 快速连续点击或连续 fragment 提交触发频繁 target 更新时，WGPU 子进程可能退出非零。
- 推测根因是新 `ActiveTransition` 创建时，从旧 transition 的原始 `from`、旧 target 和当前 sampled value 中取值不一致。
- `superseded` 处理缺少不可变的 frame snapshot。
- fragment tree 在采样过程中被修改，可能导致 active、exiting 和 current 三个集合不同步。

## 二、重构总览

### 2.1 四个明确层次

```text
NUI source / JSON IR
  -> motion definitions + presentation state machine
  -> visual target resolver
  -> animation command
  -> WGPU animation sampler
  -> visual frame snapshot
  -> render pass + hit-test pass
```

每层只有一个职责：

| 层 | 负责 | 不负责 |
|---|---|---|
| Schema | 定义字段、枚举、序列化契约 | 决定业务状态 |
| UI runtime | 解析 Flow、维护 presentation state、解析 target | 执行 GPU 插值 |
| Animation runtime | 管理时钟、生命周期、采样、插值 | 解释业务 intent |
| Renderer | 将 sampled visual 写入 instance、绘制和命中测试 | 创建语义状态转换 |

### 2.2 四类动画

| 动画类别 | 触发条件 | 起点 | 终点 | identity |
|---|---|---|---|---|
| `enter` | 节点首次进入 fragment | motion.from 或默认初始值 | fragment target | node id + generation |
| `transition` | fragment target visual 改变 | 当前 sampled visual | 新 target | node id + generation |
| `exit` | 节点从 fragment 消失 | 当前 sampled visual | motion.to 或隐藏值 | node id + generation |
| `presentation` | machine 状态改变 | 当前 sampled visual | state style target | node id + generation |

shader 的持续动画不属于上述有限 transition。它拥有自己的 `time_seconds` 和 typed parameter track，但仍然必须挂在明确的 layer、program revision 和 frame sequence 上。

## 三、动画数据模型

### 3.1 UiNode 生命周期槽位

```rust
pub struct UiNode {
    // existing fields

    /// 任意 visual target 变化时使用
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub transition: Option<UiTransition>,

    /// node identity 首次进入 fragment 时使用
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub enter_transition: Option<UiTransition>,

    /// node identity 从 fragment 消失时使用
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub exit_transition: Option<UiTransition>,
}
```

行为定义：

- `enter_transition` 只在 identity 第一次出现时触发。
- `transition` 只在 identity 仍然存在且 target visual 发生变化时触发。
- `exit_transition` 在 identity 消失后保留一个 exiting record，动画完成后才移除。
- 若旧 IR 只提供 `enter_transition`，继续按兼容规则读取，但不得再把它当作 generic transition。

### 3.2 UiVisualState

```rust
pub struct UiVisualState {
    pub bounds: Option<UiBounds>,
    pub transform: Option<UiTransform>,
    pub background_color: Option<[f32; 4]>,
    pub border_color: Option<[f32; 4]>,
    pub border_width: Option<f32>,
    pub corner_radius: Option<f32>,
    pub opacity: Option<f32>,
    pub text_color: Option<[f32; 4]>,
    pub numeric_value: Option<f32>,
}

pub struct UiTransform {
    pub translate: [f32; 2],
    pub scale: [f32; 2],
    pub rotation: f32,
    pub anchor: [f32; 2],
}
```

约束：

- 缺失属性表示“沿用当前值”，不是隐式重置为零。
- opacity 规范化到 `0..=1`。
- scale 必须是有限数，默认 `[1, 1]`。
- rotation 使用弧度，schema 层不接受 NaN 或无穷值。
- color 使用统一 RGBA 表示，插值空间在 renderer 中固定，不由调用方自行决定。

### 3.3 AnimationReason

```rust
pub enum AnimationReason {
    Enter,
    Transition,
    PresentationState,
    Exit,
    Retarget,
    Restore,
}
```

reason 必须进入诊断记录，便于区分“状态机没有切换”和“状态机已切换但动画没有执行”。

### 3.4 AnimationCommand

```rust
pub struct UiAnimationCommand {
    pub node_id: String,
    pub node_generation: u64,
    pub transition_id: u64,
    pub program_revision: u64,
    pub source_frame_sequence: u64,
    pub start_time_seconds: f32,
    pub reason: AnimationReason,
    pub from: UiVisualState,
    pub target: UiVisualState,
    pub motion: MotionSpec,
}
```

`UiAnimationCommand` 是 UI runtime 到 animation runtime 的边界。WGPU 不接收未经解析的 semantic intent，也不自行查找业务状态。

### 3.5 ActiveTransition

```rust
pub struct ActiveTransition {
    pub node_id: String,
    pub node_generation: u64,
    pub transition_id: u64,
    pub program_revision: u64,
    pub started_at_seconds: f32,
    pub motion: MotionSpec,
    pub from: UiVisualState,
    pub target: UiVisualState,
}

pub struct ExitingNode {
    pub transition: ActiveTransition,
    pub remove_after_seconds: f32,
}
```

核心集合：

```text
current_visual:  node identity -> last committed target/sample
active:          node identity -> ActiveTransition
exiting:         node identity + generation -> ExitingNode
```

所有集合以 `node_id + node_generation` 作为生命周期身份，不能只用数组索引。

## 四、统一时钟与帧模型

### 4.1 AnimationClock

```rust
pub struct AnimationClock {
    pub monotonic_seconds: f32,
    pub frame_sequence: u64,
    pub animation_epoch: u64,
}
```

- 使用 monotonic clock，不使用 wall clock。
- `frame_sequence` 是 producer/consumer 配对字段。
- `animation_epoch` 在 program、surface 或 renderer 重建时递增。
- 同一 render frame 中所有 node 使用同一个 clock snapshot。
- shader 的 `time_seconds` 和通用 motion 都从同一 runtime clock 派生。

### 4.2 VisualFrameSnapshot

```rust
pub struct VisualFrameSnapshot {
    pub program_revision: u64,
    pub frame_sequence: u64,
    pub animation_epoch: u64,
    pub nodes: Vec<SampledNodeVisual>,
}

pub struct SampledNodeVisual {
    pub node_id: String,
    pub node_generation: u64,
    pub transition_id: Option<u64>,
    pub visual: UiVisualState,
    pub lifecycle: LifecycleState,
}
```

渲染器只消费 `VisualFrameSnapshot`。在 snapshot 完成之前不能修改 fragment tree、active map 或 exiting map。

## 五、状态机职责和动画职责

### 5.1 状态机负责什么

状态机只负责离散语义：

```text
current state + event + guard
  -> next state
  -> actions
  -> visual target selection
  -> optional motion key
```

例如：

```text
menu.closed + menu.open
  -> menu.opened
  -> target menu-panel.visible = true
  -> motion = menu-reveal
```

状态机不负责：

- 每帧计算 opacity。
- 读取 GPU buffer。
- 判断一个节点何时真正被删除。
- 解释 shader 内部的距离函数或 glow 算法。

### 5.2 动画 runtime 负责什么

动画 runtime 接收 `UiAnimationCommand` 后负责：

- 选择统一时钟。
- 计算当前 progress 和 easing。
- 对 from/target 进行属性插值。
- 处理 supersede、retarget 和 exit tombstone。
- 将 transform 应用于视觉和 hit-test。
- 在完成时精确提交 target 并发布完成状态。

### 5.3 渲染器负责什么

Renderer 负责：

- 将 sampled visual 打包到 `UiInstance`。
- 在 vertex shader 应用 transform。
- 在 hit-test shader 或 CPU hit-test 中使用同一 transform。
- 按 layer/group 排序并提交 render pass。
- 将 shader parameter frame 绑定到 material。

Renderer 不负责：

- 根据 `intent` 名称猜业务动作。
- 自己创建 NUI state machine。
- 用当前鼠标坐标直接改节点 target。

### 5.4 外部 Node/XState host 边界

外部 Node host 可以使用 XState 管理应用、编辑器或测试流程，但它通过公共协议进入 runtime：

```text
Node/XState event
  -> semantic intent / input frame / presentation command
  -> neon-ui-runtime state machine
  -> UiAnimationCommand
  -> neon-wgpu-runtime sampler
```

Node 不直接调用 `sample()`，也不直接改 `ActiveTransition`。这样 runtime 内部的动画行为可以脱离 Node 单独测试。

## 六、状态机运行时集成方案

### 6.1 正确的事件流

```text
pointer / semantic intent
  -> ui.host.inbound
  -> neon-ui-runtime validates program + event
  -> NuiFlowStateMachineRuntime.dispatch
  -> state transition result
  -> apply presentation styles
  -> emit UiAnimationCommand
  -> wgpu animation runtime
  -> render frame
```

### 6.2 具体改动

1. `ui.flow.submit` 时由 `neon-ui-runtime` 初始化 `NuiFlowStateMachineRuntime`。
2. `neon-ui-runtime` 保留当前 machine state、program revision 和 presentation target。
3. `ui.host.inbound` 成功解析 semantic event 后执行 state machine dispatch。
4. dispatch 结果携带 `previous_state`、`next_state`、`motion_key` 和 `visual_target_revision`。
5. UI runtime 将结果转换为 `UiAnimationCommand` 或 immediate visual update。
6. WGPU runtime 只消费 command，并在下一帧采样。
7. completion event 返回给 UI runtime，不能直接改变业务状态。

### 6.3 状态转换结果

```rust
pub struct NuiFlowStateTransitionResult {
    pub machine_id: String,
    pub event: String,
    pub previous_state: String,
    pub next_state: String,
    pub state_revision: u64,
    pub motion_key: Option<String>,
    pub visual_targets: Vec<VisualTargetUpdate>,
}
```

`state_revision` 和 `program_revision` 分开：

- program revision 表示 Flow 程序版本。
- state revision 表示 presentation machine 的离散状态版本。
- animation transition id 表示一个具体视觉过渡实例。

三者不能相互替代。

### 6.4 不在 WGPU 中复制状态机

原方案中的以下做法取消：

```text
WgpuRuntime
  └── NuiFlowStateMachineRuntime
```

改为：

```text
neon-ui-runtime
  ├── NuiFlowStateMachineRuntime
  ├── NuiFlowDocument
  ├── VisualTargetResolver
  └── AnimationCommandPublisher

neon-wgpu-runtime
  ├── AnimationClock
  ├── ActiveTransitionSet
  ├── VisualInterpolator
  ├── TransformHitTester
  └── LayerCompositor
```

如果进程边界要求 WGPU 独立接收命令，则只共享 `UiAnimationCommand`，不共享完整的 state machine context。

## 七、快速切换和重定向算法

### 7.1 Retarget 规则

当同一 identity 在动画未完成时收到新 target：

```text
old active transition
  -> sample at current AnimationClock
  -> sampled value becomes new from
  -> new fragment value becomes new target
  -> transition_id increment
  -> atomically replace active transition
```

严禁：

- 使用旧 transition 的原始 `from` 作为新 from。
- 使用旧 target 作为新 from。
- 在 sample 中修改 fragment tree。
- 同一 frame 中同时写 active、current 和 exiting 的半成品。

### 7.2 伪代码

```rust
fn retarget(
    active: Option<&ActiveTransition>,
    target: UiVisualState,
    clock: &AnimationClock,
    motion: MotionSpec,
) -> ActiveTransition {
    let from = match active {
        Some(previous) => sample_transition(previous, clock.monotonic_seconds),
        None => target.clone(),
    };

    ActiveTransition {
        node_id: active.map(|v| v.node_id.clone()).unwrap_or_default(),
        node_generation: active.map(|v| v.node_generation).unwrap_or(0),
        transition_id: next_transition_id(),
        program_revision: active.map(|v| v.program_revision).unwrap_or(0),
        started_at_seconds: clock.monotonic_seconds,
        motion,
        from,
        target,
    }
}
```

真实实现不能使用上面的默认 identity 逻辑，必须由调用方先提供稳定的 node identity；伪代码只展示 from 的采样原则。

### 7.3 同一帧批处理

一次 fragment 更新中如果有多个节点变化：

1. 先读取旧 fragment snapshot。
2. 计算所有 node 的 target。
3. 对所有 active transition 做同一 clock 的采样。
4. 生成一批新的 `UiAnimationCommand`。
5. 一次性替换 active map。
6. 生成不可变 `VisualFrameSnapshot`。

不允许按节点顺序边采样边修改 active map，因为节点顺序不应改变动画结果。

## 八、Enter、Exit 和重新出现

### 8.1 Enter

节点 identity 第一次出现：

```text
identity absent
  -> create current visual from target or initial state
  -> apply enter motion
  -> insert active
```

如果节点只是同一 fragment 内的普通属性更新，不得再次触发 enter。

### 8.2 Exit tombstone

节点从新 fragment 消失时：

```text
active node
  -> move to exiting[node_id, generation]
  -> keep render record
  -> sample exit transition
  -> remove after completion
```

exiting 节点的 hit-test policy 必须显式定义：

- 默认不再接收新的业务点击。
- 可以继续接收 pointer leave，以便清理 hover。
- 如果产品需要 exit 期间可交互，必须单独声明 `exit_interactive true`。

### 8.3 Reappear

相同 node key 在 exit 期间重新出现：

1. 比较新旧 generation。
2. 取消旧 exit tombstone。
3. 在同一个 clock 采样当前 exiting visual。
4. 以 sampled value 作为新 enter/transition 的 from。
5. 新 generation 递增，旧 completion event 不能删除新节点。

### 8.4 完成和删除

动画完成时：

- sampled visual 精确写成 target。
- active transition 从 active map 移除。
- target 写入 current visual。
- exit 节点只有在 completion event 被确认后才从 render list 移除。
- completion event 带 `node_generation` 和 `transition_id`，旧 event 必须被丢弃。

## 九、属性插值和 Transform

### 9.1 插值策略

| 属性 | 插值方式 | 备注 |
|---|---|---|
| bounds | 分量线性或 easing | x/y/w/h 必须同时采样 |
| opacity | 标量 | clamp 到 0..1 |
| background/border/text color | 固定色彩空间的 RGBA 插值 | 不能混用不同色彩空间 |
| border width | 标量 | 非负 |
| corner radius | 标量 | 非负并受 bounds 限制 |
| numeric value | 标量 | slider/progress 使用 |
| translate | vec2 | 与 bounds 分开 |
| scale | vec2 | 不允许零或负值，除非显式支持反射 |
| rotation | 最短弧或指定方向 | schema 明确方向 |
| shadow/blur/bloom | shader parameter | 不塞入普通 UI state |

### 9.2 Transform 应用

```wgsl
let center = rect.xy + rect.zw * transform_anchor;
let local = vertex_position - center;
let scaled = local * transform_scale;
let rotated = rotate_2d(scaled, transform_rotation);
let final_position = rotated + center + transform_translate;
```

必须同时应用到：

- 普通 visual vertex shader。
- text quad 的 vertex transform。
- clip/bounds 计算。
- hit-test shader 或 CPU hit-test。
- debug bounds 和 inspector 结果。

### 9.3 Hit-test 一致性

hit-test 不能继续使用未变换的 axis-aligned bounds 作为最终命中依据。至少需要：

1. 将 pointer 从 window-local 转为 node-local。
2. 使用 inverse transform 计算局部坐标。
3. 按节点 clip 和 visibility policy 判断。
4. 返回 node id、generation 和 frame sequence。

## 十、Shader 参数动画边界

shader 参数是动画系统的扩展轨道，不是 presentation state 的替代品。

### 10.1 ShaderParameterTrack

```rust
pub struct ShaderParameterTrack {
    pub package_id: String,
    pub package_version: u32,
    pub parameter_name: String,
    pub kind: ShaderValueKind,
    pub keyframes: Vec<ShaderKeyframe>,
}

pub struct ShaderKeyframe {
    pub offset: f32,
    pub value: ShaderParameterValue,
}
```

### 10.2 边界规则

- `time_seconds` 由 WGPU runtime 的统一 clock 提供。
- 外部 progress 可以作为 typed parameter 传入，但不能伪造 runtime clock。
- shader 不能修改 node identity、fragment target 或 state machine state。
- shader package 注册、material binding 和实际绘制必须分开诊断。
- shader fallback 失败时，通用 UI transition 仍然必须可以运行。
- 参数更新记录 package、version、source digest、frame sequence 和 animation epoch。

### 10.3 LayerCompositor

通用 layer 类型：

```text
behind_glass
normal
overlay
debug
```

动画系统只负责 layer 中节点的生命周期和采样；compositor 负责：

- layer 顺序。
- 同一 node/material 是否重复绘制。
- exiting node 是否继续出现在正确 layer。
- animation completion 后的 remove。
- debug capture 与实际 render pass 的对应关系。

## 十一、NUI 语法扩展

### 11.1 Motion 定义

```text
motion fade-in duration 300 easing ease_out
  from opacity 0

motion slide-up duration 400 easing ease_out
  from translate 0 24 opacity 0

motion pop duration 200 easing ease_out
  from scale 0.92 opacity 0

motion rotate-in duration 600 easing ease_out
  from rotation -0.25 opacity 0
```

### 11.2 节点引用

```text
panel main-panel
  enter fade-in
  exit slide-up
  transition pop
```

### 11.3 状态机引用

```text
machine menu initial closed
state menu closed
state menu opened
on menu open -> opened
on menu close -> closed
transition menu closed -> opened motion menu-reveal
transition menu opened -> closed motion menu-hide
```

状态机 transition 和节点 generic transition 的优先级：

```text
explicit state transition motion
  > node transition
  > default runtime transition
  > immediate update
```

优先级必须进入静态 AST，不能在 renderer 中通过字符串名称猜测。

### 11.4 语法校验

parser/schema 必须拒绝：

- 未定义 motion key。
- 重复 motion key。
- duration 小于零或超过安全上限。
- 非法 easing。
- transform 数值为 NaN/Infinity。
- 同一节点的 enter/exit/transition 属性重复声明。
- 节点 key 不是稳定 identity。
- exit 目标缺少可计算的最终 visual。

## 十二、动画运行时的并发与稳定性

### 12.1 线程边界

- Flow/program 更新线程生成 immutable target snapshot。
- animation sampler 在 render loop 内消费 snapshot。
- shader parameter upload 使用 bounded queue。
- completion event 异步发布，不阻塞 render loop。
- fragment tree 不在采样过程中被其他线程原地修改。

### 12.2 Request/revision 边界

每个 animation command 至少携带：

```text
program_revision
state_revision
transition_id
node_generation
source_frame_sequence
animation_epoch
```

收到旧 program revision、旧 generation 或旧 animation epoch 的 command：

- 不进入 active map。
- 记录 rejected/stale 原因。
- 不影响当前可见 frame。

### 12.3 Backpressure

- animation command queue 有上限。
- 相同 node identity 的过时 target 可以合并，但必须保留最后 target 和当前 sampled from。
- 不允许无界累积每一次鼠标 move 的动画命令。
- render loop 忙时保留最近完整 frame，不显示半成品 frame。
- completion event 采用 bounded queue，丢弃旧的 superseded completion。

### 12.4 崩溃保护

遇到非法 visual、无效 transform、未知 node generation 或超大 animation queue：

1. 拒绝当前 command。
2. 输出结构化诊断。
3. 保留最后合法 visual frame。
4. 不让单个节点错误终止整个 WGPU 进程。

## 十四、真实行为探针

编译通过不是动画验收。所有跨进程、状态机和 GPU 行为必须有固定输入、显式 timeout、bounded polling、结构化 JSONL 和反映结果的 exit code。

### 14.1 `animation-retarget-probe`

固定对同一 node 连续提交 100 次 target：

- opacity 0 -> 1 -> 0。
- translate 左右切换。
- scale 和 rotation 交替变化。

断言：

- WGPU 进程不退出。
- 每次新 from 等于旧 transition 的当前 sample。
- `transition_id` 单调递增。
- 最后一帧精确等于最后 target。

### 14.2 `animation-lifecycle-probe`

固定序列：

```text
submit A -> enter A
submit B -> exit A + enter B
submit A before exit completes -> cancel exit + retarget A
```

断言：

- 旧 generation 的 completion 不能删除新 A。
- exit 节点在 completion 前仍可观察。
- remove 只发生一次。

### 14.3 `animation-state-machine-probe`

固定提交 NUI machine、motion 和 semantic event：

- 记录 previous state、next state、state revision。
- 记录 motion key 和 visual target。
- 检查 `UiAnimationCommand` 的 program/state/transition revision。
- probe 不再手写 if-else 修改样式。

### 14.4 `animation-transform-hit-probe`

固定 scale、rotation、translate、anchor 和 pointer：

- 记录 producer logical coordinate。
- 记录 consumer local coordinate。
- 记录 inverse transform 结果。
- 记录 node id、generation、frame sequence。
- 区分坐标错位、generation stale 和 hit-test 方向错误。

### 14.5 `shader-parameter-probe`

只验证通用 shader 动画边界：

- package manifest、version、digest。
- parameter type 和范围。
- frame sequence 与 animation epoch。
- 两个 paired frames 的参数变化。
- shader 失败时 fallback 和通用 transition 仍然存在。

### 14.6 JSONL 记录格式

```json
{
  "probe": "animation-retarget.v1",
  "sequence": 7,
  "input": {
    "node_id": "panel-a",
    "reason": "retarget",
    "target": {
      "opacity": 1,
      "transform": {
        "translate": [0, 0],
        "scale": [1, 1],
        "rotation": 0,
        "anchor": [0.5, 0.5]
      }
    }
  },
  "producer": {
    "program_revision": 4,
    "state_revision": 11,
    "transition_id": 18,
    "node_generation": 3,
    "frame_sequence": 188,
    "animation_epoch": 2
  },
  "consumer": {
    "sampled_from": { "opacity": 0.63 },
    "sampled_target": { "opacity": 1 },
    "render_status": "accepted"
  },
  "pairing": {
    "producer_frame": 188,
    "consumer_frame": 188,
    "status": "matched"
  },
  "result": "passed",
  "pass_result": true
}
```

## 十七、最终验收标准

1. 快速连续 target 更新 10 秒不崩溃，100 次 retarget 无 WGPU 进程退出。
2. 新 transition 的 from 永远等于旧 transition 在同一个 `AnimationClock` 下的 sampled visual。
3. enter、transition、exit 三种原因可以被诊断记录区分。
4. exit 节点在动画完成前不会直接消失。
5. 同一 key 重新出现时，旧 generation 的 completion 不会删除新节点。
6. transform 后的视觉位置与 hit-test 位置一致。
7. NUI 声明 state machine 和 motion 后，真实 runtime 可以自动产生动画 command，不需要 probe 手写 if-else。
8. program revision、state revision、transition id、generation、frame sequence 互不混用。
9. shader 参数轨道不会修改状态机和节点生命周期。
10. 非法 command 只拒绝当前更新并保留最后合法 frame，不终止整个 renderer。
11. 每个真实行为 probe 输出 input、producer、consumer、pairing 和最终 pass/fail。
12. 状态机和动画系统可以脱离具体案例单独测试，案例只作为回归调用方。

## 十八、明确不在本文解决的问题

- IDE 的文档模型、编辑器 UI 和 XState app machine。
- Windows Acrylic、窗口布局和具体视觉主题。
- 某个音乐、游戏或业务案例的领域状态。
- 具体 shader 的艺术效果和颜色设计。
- World UI 的相机、深度和跨引擎表面协议。

这些系统可以调用本方案提供的状态转换和动画 command，但不能反过来改变动画核心的职责边界。
