# 2026-08-18

## neon-eventd 事件模块协议设计

- 用户决定新增独立事件中转模块 `neon-eventd`（此前我建议收敛到 sessiond，用户明确
  要求提纯为独立模块），统一中转、走专用事件协议，含高速接口。
- 产出：`plan/neon3-eventd.md`，定义 `neon3.event` 专用协议（EventEnvelope、
  publish/subscribe/ack、schema registry、epoch+全局单调 sequence、幂等、
  环形缓冲重放、断线重连补齐），以及共享内存 SPSC ring fast path（对齐 AGENTS.md
  26.3 契约）与降级策略。
- 核心边界（沿用 AGENTS.md）：变量变动事件是观测通知，不是业务命令；事件 payload
  不携带 GPU handle / element ID / 文件路径；接收方不得把事件当权威状态。
- 未决决策（见文档第 12 节）：环形缓冲默认容量、service.subscribe 保留与否、
  订阅端 ring 首版不做、严格模式默认是否开启。

### 已确认决策（当日补充）

- 严格模式默认开启，未注册事件名直接拒绝。
- 环形缓冲默认 4096 条，可用 `event.retention.get/set` 调整。
- 保留旧 RPC polling `service.subscribe`，平稳迁移。
- 订阅端 ring 首版不做，统一由 eventd fan-out 后走 TCP。

### neon-eventd 实施完成（当日补充）

按 plan/neon3-eventd.md 第 11 节完成全部 5 项：

1. `neon-protocol`：新增 `neon3.event` 专用协议类型（`EventFrame`/`EventResponse` tagged enum、
   `EventEnvelope`/`EventPublish`/`EventSubscribe`/`EventAck`/`EventFilter`/`EventSnapshot`/
   `EventRetention`/`EventError`），publish/subscribe 均带 request_id。
2. `neon-ipc`：公开泛型 `read_json_frame`/`write_json_frame`，`RpcServer::accept()` 支持长连接
   推送，新增 `EventClient`（publish/subscribe 流）。
3. 新建 `neon-eventd` crate：事件注册表（严格模式，预注册 9 个保留命名空间）、全局单调
   sequence、订阅表（filter OR 语义）、4096 条环形缓冲、幂等去重、RPC 控制面
   （service.*/event.snapshot/schema/retention/stats/fastpath.status）、事件服务端按帧
   `protocol` 字段分发 RPC/Event，writer 线程统一写帧。11 个单元测试 + loopback 集成测试。
4. `neon-ui-runtime`：`UiInputApplyResult` 增加 `variable_changes`（含 kind/old/new），
   新增 `event_publisher.rs` 的 `UiVariableEventPublisher`（best-effort 发布
   `nui.variable.changed`），`DemoInputDomain` 加 `with_publisher` 接入。
5. `neon-cli`：新增 `neon event snapshot/subscribe` 命令，`EventCommand` 解析与执行，
   阻塞收 8 条事件后输出。端到端 Python 验证 publish→订阅广播成功。

遇到的坑：
- BufWriter 写帧后必须 flush，否则客户端收不到。
- 订阅 forwarder 线程持有 write_tx clone，Unsubscribe 后需先移除 subscriber 再 join writer
  线程，否则死锁。
- `handle_connection` 必须先读 Value 按 protocol 分发，否则 RPC 帧被当 EventFrame 解析失败。
- Windows target 目录 .cargo-build-lock 偶发"拒绝访问"，删除锁文件或等释放即可。

### NUI Flow `emitevent` 定向事件（当日补充）

- 用户需求：NUI Flow 变量变化时可在 input 行声明 `emitevent`，自动向事件中心发事件。
- 决策：input 行尾部 `emitevent` 属性；新增 `flow <name>` 声明行；事件名 `flow.<文件名>.<变量名>`。
- 实现：
  - `neon-ui-schema`：`UiInputSchema` 增加 `flow_name: String` 与 `emit_event_keys: Vec<String>`
    （均 `#[serde(default, skip_serializing_if)]`，旧 JSON 兼容）。
  - `nui_flow.rs`：Header 加 flow_name；parse_header 解析 `flow <name>`（valid_key 校验）；
    parse_input 解析尾部 `emitevent`（grid input 拒绝）；format 保留两者。
  - `event_publisher.rs`：`UiVariableEventPublisher` 新增 flow_name/emit_event_keys，
    只发布声明了 emitevent 的变量，事件名 `flow.<flow_name>.<key>`；未声明变量静默；
    `event_name_for()` 判定；`EVENT_VARIABLE_CHANGED` 保留兼容。
  - `demo_domain.rs`：新增 `with_schema_publisher(endpoint, client, module, surface)`，
    从 schema 自动提取 flow_name/emit_event_keys。
  - `neon-eventd`：预注册 `flow.` 命名空间（严格模式放行）。
  - fixture `imgui-component-gallery.nui`：加 `flow component-gallery`，
    `feature_enabled` 加 `emitevent`。
- 新增测试：flow 解析（flow+emitevent、缺 flow 声明、grid emitevent 拒绝、format 保留）、
  event_publisher 定向过滤、demo_domain 端到端（事件名 flow.component-gallery.feature_enabled）。
- 全量通过：protocol 22 / ipc 11 / eventd 11 / cli 9 / ui-runtime 93。端到端 Python 验证
  flow 事件 accepted、未知命名空间 rejected、snapshot 含 flow. 命名空间。
- 设计文档已更新：`plan/neon3-nui-flow.md` 新增 "Directed variable events (emitevent)" 小节。
