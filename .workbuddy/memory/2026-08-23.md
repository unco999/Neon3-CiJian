## bevy-nui-host demo 两个问题的排查（续 08-22 大改造）

### 1. `Entity despawned` 报错（我的回归，已修）
- 现象：`Entity despawned: entity 2663v0 is invalid; index now generation 1`。
- 根因：`despawn_fox_girl_helper_cube` 里对 `Cube_286`（盒子父节点）和 `Object_283`（盒子叶子）**同时** despawn。Bevy 0.19 的 `despawn()` 是**递归**的——`despawn(Cube_286)` 已递归删掉子节点 `Object_283`，再显式 `despawn(Object_283)` 等于对一个父节点已消失的叶子二次 despawn，触发 Bevy 的 "entity despawned" 守卫。
- 修复：despawn 列表从 `"Cube_286" | "Object_283" | "Object_9"` 改为 `"Cube_286" | "Object_9"`（`Cube_286` 递归覆盖盒子，`Object_9` 是地面 plane 叶子）。
- 教训：**Bevy 0.14+ `despawn()` 递归，别再同时 despawn 父+子**；`despawn_recursive` 在 0.19 已移除。

### 2. 点击 `ui.host.inbound failed: os error 10061`（遗留，未修）
- 现象：点击怪物/按钮，`[neon-ui-runtime] ui.host.inbound failed: transport_io ... 10061` + `bevy_pointer_response accepted:false service_unavailable`。
- 定位（逐行追）：bevy 点击 → `ui.host.inbound(pointer_event)` → forwarder `forward_host_request` → `ensure_host_adapter(domain_endpoint=39104)` → `RpcClient::connect(39104)` 被拒。`ui_perf_window` 里 `pointer_down_received:0` 证明指针死在到达 wgpu 之前（在 `ensure_host_adapter` 这步）。
- 根因：`domain_endpoint`（127.0.0.1:39104）是**占位、从不监听**（08-18 memory 就记过 "domain 占位 39104 不起"）。`ensure_host_adapter` 只有在 `self.host_adapter` 为 None 时才去连 39104；而 `host_adapter` 本应由 `ui.flow.submit`（`forward_flow_source` 第 3182 行 `self.host_adapter = Some(adapter)`）在流程提交成功时设置。
- 关键待确认矛盾：`ui_perf_window` 里 `unified_id_passes:1` + `rendered_frames:14` 说明片段**确实渲染**（流程编译/转发成功）→ `host_adapter` 理应已设置 → 不该去连 39104。但日志显示它确实连了。最可能：**`ui.flow.submit` 失败**（我改 `monster_field_flow()`/`status-flow.nui` 引入 NUI Flow 语法错），导致 `host_adapter` 保持 None。
- 待用户确认：启动日志里搜 `bevy-flow-source-0`。若出现 `rejected: ui_flow_submit_failed` + `detail: NUI parse/compile failed ...` 即流程语法错（我修 flow）；若 accepted 但点击仍 10061，则是 forwarder 的 `host_adapter` 未从直接提交路径正确激活（我改 ui-runtime）。
- 关联：这条链路也挡住摄像机动画——`intro.go_city/go_girl` 按钮点击走的就是 `ui.host.inbound`，点击被拒就发不出 intent，相机不会动。修好这条，摄像机动画才能跑。

## 根因找到并已修（「什么都不显示」+ 10061 是同一个根因）

用户反馈「还是什么都不显示」+ 10061。定位到 NUI Flow 两个硬错误，导致 `ui.flow.submit` → `parse_nui_flow` 直接失败 → 无 fragment → 什么都不显示；`host_adapter` 保持 None → 点击走 `ensure_host_adapter(39104)` → 10061。**两个现象同源：flow 解析失败。**

1. **node key 重复**：`status-flow.nui` 里 `intro-city` 和 `intro-girl` 两个 branch 都放了 `button go-welcome`（同名）。NUI Flow 硬约束 `node keys must be unique across the Flow document`（`nui_flow.rs:228-229`），node id **全局唯一、不按 branch 作用域隔离**。修：改成 `go-welcome-city` / `go-welcome-girl`（`event intro.go_welcome` 不变）。
2. **预算超限（两次）**：先 `budget nodes=512` 超限；实测（`cargo test monster_world_flow_contains_all_catalog_panels_and_inputs`）又报 `UiProgramCompileError { code: "ui_program_capacity_overflow", message: "clip count exceeds the declared program budget" }`——**clip 数超限**（每个 panel 默认 clip 子元素，50 怪物×3 panel + 屏幕 + 狐女 ≈ 158，但实际超 512）。最终 budget 全量调大：`nodes=2048 bindings=1024 instances=1024 text=1024 glyphs=32768 events=1024 clips=4096`。测试通过（parse + compile 都过）。

**关键教训（NUI Flow 易错点，务必记牢）**：
- node key（panel/text/button/branch/… 的第一个词）**必须全 Flow 文档全局唯一**，不能在不同 branch 里重名（不像 HTML 可以按父节点作用域隔离）。
- `budget nodes=N` 是 wgpu 硬性上限（`ui_program_gpu.rs:86 fits_budget` 拒绝超限 fragment），加节点时必须同步加预算。50 个 `world panel`（不是 repeat）每个都是独立 node，各占一个 node 计数。**还有 `clips` 维度**：每个 panel 默认 clip 子元素，`clip count` 也受 `budget clips=N` 限制，改 UI 时 node/clips/bindings/text 都要一起看。
- 排查「什么都不显示」时应先怀疑 flow 编译失败（`ui.flow.submit` → `parse_nui_flow`/`compile_nui_flow_program`），而不是先怀疑渲染/传输；`ui.host.inbound` 的 10061 常是 flow 失败导致的次生症状（host_adapter 没被设置）。
- **实测比手推靠谱**：bevy host 的测试 `cargo test monster_world_flow_contains_all_catalog_panels_and_inputs` 会跑 `parse + compile`，`.expect` 的 panic 直接打印精确错误码（如 `ui_program_capacity_overflow`）。改 flow 后先跑它。

## 新案例：物理游乐场 physics_playground（bevy_rapier3d + world UI 跟随 + 点击施力）

按用户要求新增独立启动入口 `src/bin/physics_playground.rs`，用 bevy_rapier3d 做物理，各种形状（球/方块/胶囊/圆柱）带发光材质 + world UI 标签跟随 + 点击标签施力（踢一脚）+ 屏幕 UI 面板调碰撞/灯光。

### 关键 bug 修复（lib.rs，也修好旧 demo 的「无法点击切换」）
`consume_neon_responses`（lib.rs:2042 附近）对 `bevy-pointer-` 响应只找 `semantic_event`，但指针现在已走 UI runtime 直接返回 `semantic_intent`，导致点击语义事件根本没进 `Neon3SemanticIntentEvents`。改为对 `bevy-pointer-` 响应直接 `semantic_intent_from_result` 提取并 push。**这是旧 demo「无法点击切换」+ 新 demo「点击施力」的共同前置**。

### bevy_rapier3d 0.35（bevy 0.19 对应版本）API 要点（易错）
- `Velocity` 字段是 `linear`/`angular`（**不是**旧版 `linvel`/`angvel`）。
- `RapierConfiguration` 是 **Component 不是 Resource**（`#[derive(Component)]`），改全局重力要用 `Query<&mut RapierConfiguration, With<DefaultRapierContext>>` 而不是 `ResMut<RapierConfiguration>`；`gravity` 字段是 `Vect`（=Vec3）。
- 碰撞体构造：`Collider::ball(r)` / `cuboid(hx,hy,hz)` / `capsule_y(half_height,radius)` / `cylinder(half_height,radius)`；`Restitution::coefficient(f)` / `Friction::coefficient(f)`；`Damping { linear_damping, angular_damping }`。mesh 用 Bevy 原语 `Sphere/Cuboid/Capsule3d/Cylinder`（全尺寸），collider 用半尺寸，要匹配。
- 施力直接改 `Velocity`（`Query<&mut Velocity>`）最简单；插件 `RapierPhysicsPlugin::<NoUserData>::default()`。

### 新 demo 设计
- flow 生成：屏幕 UI（`physics-playground.nui`，纯 button + 独立 intent，无 statechart/branch，规避了旧 demo 的 branch gating 坑）+ 120 个 `world panel phys-tag-{id}`（预生成到 MAX_OBJECTS，动态 spawn 复用已有标签）。anchor 用 `phys.obj.{id}`（不是 monster.m，故 `flush_character_status` 跳过其 var flush——标签是静态文字，无需 flush；但屏幕 UI 的 health/mana/level 会 flush，所以 flow 里必须 `input health/mana/level` 声明）。
- intent：`phys.kick.{id}`（点击标签施力）、`phys.gravity.{low|earth|jupiter}`、`phys.bounce.{soft|normal|bouncy}`、`phys.friction.{slick|normal|sticky}`、`phys.light.{dawn|noon|dusk|neon}`、`phys.spawn/clear/fireworks/well`。施力/引力井直接改 `Velocity`，碰撞/重力/灯光由 `apply_gravity_well` + `apply_light_preset` 每帧同步。
- 灯光：暖色 ambient + 方向光 + 冷暖两个点光源 + emissive 材质 + Bloom + Hdr + Msaa::Sample4；`LightRig` resource 存 Entity，`apply_light_preset` 按 preset 改颜色。
- 编译：`cargo check --bin physics_playground` 通过（exit 0，仅 neon-wgpu-runtime 等既有 dead-code 警告）。运行 `cargo run --bin physics_playground`。
- 世界 UI 相机 ID 硬编码 `bevy.main.camera`（lib.rs:2388 `publish_camera_snapshot`），flow 里 `camera 3d:bevy.main.camera` 对齐。
