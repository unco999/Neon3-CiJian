## 「两路颜色、一路深度」双 surface 方案实现（用户昨晚定的架构，本轮落地）
### 目标
- world surface：world_color + world_depth（R32Float）→ Bevy 按深度与场景合成
- screen surface：screen_color（无深度）→ 最后无深度覆盖
- 同一 combined Flow、同一 buffer index/frame sequence；不再用 0.0/0.001 特殊深度标记

### 关键发现：Bevy host（/d/bevy-nui-host，独立仓库）昨晚已实现大部分
- 双 surface 请求（screen/world）+ 双 pass composite（world 深度遮挡 + screen 覆盖）已存在
- `Neon3ExternalSurfaceGpu` 有 imported_colors/imported_world_colors/imported_depths/imported_world_depths
- 缺的是 **WGPU producer 内容分流**（两个 surface 都画全量内容）

### 本轮改动
1. **ui_renderer.rs**：
   - 新增 `UiDrawMode { All, World, Screen }`；`draw()` 加 mode 参数，按 `world_depth.is_some()/is_none()`
     过滤 instance/images/surfaces/texts/popup（popup/modal/tooltip/text-input 只属 screen，World mode 跳过）
   - `draw_depth()` 去掉 `EXTERNAL_WORLD_DEPTH_MIN=0.001` 特殊编码，直接输出 [0,1] world_depth（删除该常量）
2. **lib.rs（neon-wgpu-runtime）**：
   - 修复 `retain_surface_nodes`：加 `inherited_world` 参数（world 子树整体归属），WorldUi 分支用
     `is_world || !children.is_empty()`（透明 root 容器保持可见，否则 flatten 的 `!visible` 直接 return 丢子树）
   - `external_surface_snapshots()` 返回 `(split, combined)`；`render()` 加 `combined` 参数
   - ID pass 改用 `combined`（统一 ID 图 = 全部 UI 的 hit binding，不再按 surface 分裂）
   - render 按 `surface_kinds[surface_id]` 传 `UiDrawMode::World/Screen` 给 draw
3. **bevy-nui-host**：`request_screen_surface` 的 `depth: false`（screen 不再要 depth ring；import 对无 depth 已优雅跳过）

### 验证
- neon-wgpu-runtime：`cargo test --lib` 120 passed（含新增 `retain_surface_nodes_keeps_world_subtrees_and_screen_ui_separate`）
- bevy-nui-host：`cargo check` 通过（incremental 目录偶发拒绝访问警告，无碍）
