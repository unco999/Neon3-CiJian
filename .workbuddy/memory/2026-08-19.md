## 三缓冲 D3D12 interop 死锁修复（08-19，用户报"坐标更新但纹理不重绘"）
- 根因：producer `min_by_key(frame_sequence)` 挑最旧 buffer + GPU `Wait(consumer_fence)`；consumer `max_by_key(fence)` 只采样最新 buffer 且只释放这一个。producer 跑快时前 3 帧填满 3 个 buffer，第 4 帧等 buffer0 释放，而 consumer 永不释放 buffer0/1 → producer 卡死、画面冻结在旧帧。
- 修 producer（neon-wgpu-runtime/src/lib.rs `HeadlessExternalGpu::render`）：改 `min_by_key`+`Wait` 为 CPU 侧 `consumer_fence.GetCompletedValue() >= frame_sequence` 找真正空闲 buffer，无空闲则**丢帧**（`eprintln! drop frame`）而非 GPU 等死。
- 修 consumer（bevy-nui-host/src/lib.rs `neon3_external_surface_render_system`）：`pending_release`（单）→ `pending_releases`（Vec），每帧释放**所有** imported buffer（而非只释放采样那个），让 producer 真正三缓冲复用。
- 两处均编译通过；bevy-nui-host 6 tests、neon-ui-runtime 91 tests 全过。

## 怪物演示案例（bevy-nui-host）+ 多 world UI 架构修复（08-19 下午）
### 模型拆分
- `scripts/split_monsters.py`：把 `E:/game_resouce/neon2资源/模型/ultimate_monsters_pack.glb`（50 armature、9 个巨型共享 bufferView、1 个全局动画）拆成 50 个独立 .glb（`assets/monsters/*.glb`）。
- 关键坑：该 pack 用 9 个共享 bufferView 存全部顶点，必须按 accessor 精确切片（`accessor_byte_length = stride*(count-1)+elem_size`），不能整块复制；动画采样器的 input/output accessor 要重映射，且不能原地改共享 gltf dict（会污染后续怪物）。
- 校验：50/50 结构一致。

### 多 world UI 的正确架构（重要！）
- **UI runtime 只允许一个活跃 fragment**（`forward_fragment` 里 `fragment_id != cached_fragment` → `fragment_identity_change` 拒绝）。所以「N 个怪物」不能 N 个 flow，必须 **一个 flow 里放 N 个 `world panel` 节点**（每个 anchor 不同），一个 fragment 承载 N 个 world UI。
- `filter_world_panels` 会递归投影每个 world panel 到各自 anchor。

### 三缓冲 producer 死锁的根治
- 之前「按请求渲染」会在启动爆发期（50 flow+anchor 连发）把 3 个 buffer 填满、后续帧全 drop，consumer 释放后 producer 又没请求触发重绘 → 冻结。
- 改为 `spawn_headless_external_server` 里开独立渲染线程（每 16ms 渲染最新 snapshot），serve 线程只处理请求；`SharedSurface` 加 `unsafe impl Send/Sync`（HANDLE 是进程内内核句柄）。

### 其他修复
- world panel 按 camera depth 排序（far→near，近处最后画）：`filter_world_panels` 里 `visit` 记录每个面板 depth，之后对 root.children 按 depth 降序 sort。
- `NeonWorldUi` 加 `occlusion: WorldUiOcclusion { AlwaysVisible(default), DepthTested }`（为后续 UI depth target 遮挡做准备）。
- 修了一个过时测试：`world_panel_is_placed_at_the_projected_anchor_position` 期望 scale 1.0，但并发工作把公式改成 `(6.0/depth).clamp(0.5,2.0)`，depth=2→scale=2→x=630（原断言 635）。
- `pseudo_rng` 用整数哈希（避免连续 seed 线性相关导致怪物排对角线）。
- 第三人称：用现成 crate `bevy_panorbit_camera = "0.35"`（Bevy 0.19 兼容，egui 是可选依赖），`follow_character` 系统每帧把 `target_focus` 设为主角位置。
