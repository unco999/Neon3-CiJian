## bevy 点击动画无效果 —— 根因定位与修复（下午）
用户实测：点击后面板不动，日志大量 `transition start/complete` 交替 + `ui_program_stale_input_revision`。

### 根因（三个叠加）
1. **外部渲染循环时间恒为 0**：`HeadlessExternalGpu::render` 的 draw/draw_hit_id 全部传 `time_seconds=0.0`
   → `ActiveTransition` 的 elapsed 恒为 0，动画永远停在起点；且静态 snapshot 跳过会在动画中途冻结。
2. **空 changes 帧推进 input_revision**：点击时 host 无响应 → `forward_host_request` 的 fallback publication
   （`changes: Vec::new()`）应用后 `UiInputStore::apply` 仍把 revision 0→1；Bevy 的 expected_input_revision 不同步。
3. **Bevy 只从 `nui-flow:` 前缀响应同步 revision**：点击响应（`bevy-pointer-N`）里明明带 `input_revision`（ui-runtime lib.rs:3585），
   但 `consume_neon_responses` 只处理 nui-flow 前缀 → expected 停在 0 → 下一帧输入帧 stale 被拒 → health 永远不变。

### 修复（三处）
1. `neon-wgpu-runtime/src/lib.rs`：`HeadlessExternalGpu` 加 `started_at: Instant`；render() 计算
   `time_seconds = started_at.elapsed()` 传给 draw/draw_hit_id；静态跳过条件排除 `has_active_animation`
   （动画期间不跳帧）。
2. `neon-ui-runtime/src/lib.rs` `UiInputStore::apply`：`frame.changes.is_empty()` 时不推进 input_revision
   （无输入变化=状态未变；治本，fallback 空帧不再导致 stale）。
3. `bevy-nui-host/src/lib.rs` `consume_neon_responses`：revision 提取移到所有 Accepted 响应（不再限
   nui-flow 前缀），`expected_input_revision = max(旧, 新)`。

## bevy 点击动画仍无效果 + 指针疯狂刷屏 —— 根因修复（第三轮）

用户实测：点击后动画仍无效果，且"鼠标动就疯狂发信息、不动就不发"。
日志特征：`transition start/complete` 无限交替 + `press_without_semantic_hit`/`pointer_release_rejected`。

### 根因（三个叠加，全在 headless external GPU 路径）
1. **`HeadlessExternalGpu::pointer_event` 用 `time_seconds=0.0`** 调 `prepare_interaction`/`press_hovered`。
   window 版 `external_pointer_event` 用 `gpu.started_at.elapsed()`，headless 版漏改。
   后果：每次鼠标 move/down/up 都让 `sample` 以 0.0 采样 → active 里 started_at 被重置为 0 →
   渲染循环 `has_active_animation(真实时间)` 立即判定过期 complete → start/complete 疯狂交替。
   "鼠标动就发、不动就不发" 正是这个机制。
2. **动画 complete 后 `current` 没 pin 到精确 target**。`has_active_animation` 完成时只移除 active，
   `current` 保留最后一次 progress<1.0 的插值。残留的 `enter_transition`（fragment 里持久存在）让
   下一次 `sample` 把这个不完整插值当新 from 重新 start → no-op 动画反复重播。
3. **`sample` 里 `source == target` 时仍 start**，动画已到达终点仍会重播。

### 修复（crates/neon-wgpu-runtime）
1. `lib.rs` `pointer_event`：加 `let now = self.started_at.elapsed().as_secs_f32()`，
   `prepare_interaction`/`press_hovered` 传 `now` 替代 `0.0`。
2. `ui_renderer.rs` `has_active_animation`：complete 时把 `active.target` 精确写入 `self.current`
   （pin 到终点），不再残留不完整插值。
3. `ui_renderer.rs` `sample`：`source == target` 时直接返回 target 并更新 current，不再 start no-op 动画。
